## 摘要
由于视觉语言模型（VLM）对内存和计算资源的高需求，在移动设备上部署它们颇具挑战性。我们提出了一种用于在资源受限硬件上高效推理的VLM量化框架。我们的方法结合了一个量化流程——该流程利用模型自身生成训练数据，且无需访问训练设置——以及一种新颖的、支持Arm CPU高效执行的每参数2.7位格式。我们通过将Llama 3.2 11B Vision Instruct模型压缩至3.7 GB且激活值为8位，并在一系列标准视觉问答任务上保持强劲性能，验证了我们的方法。

## Abstract
Deploying vision-language models (VLMs) on mobile devices is challenging due to their significant memory and compute requirements. We present a framework for quantizing VLMs for efficient inference on resource-constrained hardware. Our approach combines a quantization pipeline that uses the model itself to generate training data and does not require access to the training setup, with a novel 2.7-bit-per-parameter format supporting efficient execution on Arm CPUs. We validate our approach by compressing the Llama 3.2 11B Vision Instruct model to 3.7 GB with 8-bit activations, preserving strong performance on a set of standard visual question answering tasks.

### 2. 方法论：核心思想、关键技术细节与流程

#### 2.1 整体框架

论文提出了一套三阶段的量化框架，适用于无原始训练数据访问权限的实际场景：

1. **合成数据生成（Synthetic Data Generation）**：利用**模型自身**生成用于量化感知训练的样本。
2. **量化感知训练（QAT）**：选定量化格式后，使用合成数据将原始全精度模型（教师）蒸馏至量化模型（学生）。
3. **移动端部署（Mobile Deployment）**：在 Arm CPU 上利用训练好的量化权重执行推理。

#### 2.2 量化感知训练（QAT）与知识蒸馏

- 设教师模型为 $f_T(\cdot; \theta_T)$（bfloat16 全精度），学生模型为 $f_S(\cdot; \theta_S)$（量化参数 $\hat{\theta}_S = Q(\theta_S)$）。
- 前向传播使用量化参数，反向传播通过**直通估计器（Straight-Through Estimator）**传递梯度。
- 蒸馏损失函数为教师与学生在生成响应 token 上的 **KL 散度（Kullback–Leibler Divergence）**：

$$\mathcal{L}_{\text{KD}}(I, x, y) = \frac{1}{|y|} \sum_{t=1}^{|y|} D_{\text{KL}}(p_T^{(t)} \| p_S^{(t)})$$

其中 $p_T^{(t)}$ 和 $p_S^{(t)}$ 分别为教师和学生模型在第 $t$ 个 token 上的预测分布。

#### 2.3 合成数据管道（S3D8 数据生成部分）

- **图像来源**：ImageNet 训练集（1,281,167 张自然图像），与下游评估任务无关，保证数据通用性。
- **文本生成**：将图像与随机采样的提示词输入教师模型（Llama 3.2 11B Vision Instruct），使用 temperature=0.6、top_p=0.9、最大生成长度 512 tokens 采样响应。
- **提示词采样策略**（关键创新）：
  - 以 $p_{\text{temp}}=0.75$ 的概率应用指令微调模板（`<|start_header_id|>user<|end_header_id|>...`），其余概率使用普通模板。
  - 问题池包含手写通用提示（如 "Describe the image."）与程序化生成的提示（形如 {action} {target} {audience} {style}），共 **495 个基础提示**。
  - 以 $p_{\text{inst}}=0.7$ 的概率附加指令块，内部可包含遵循探针（$p_{\text{adh}}=0.4$）、长度约束（$p_{\text{len}}=0.75$，短/中/长响应分别以 0.40/0.38/0.22 的概率选择）和格式要求（$p_{\text{fmt}}=0.45$）。
- **与固定提示的对比实验**证明，多样化的采样提示显著优于单一固定提示（如 "Describe the image:"），因为固定的提示导致模型输出多样性有限，损害下游泛化能力。

#### 2.4 S3D8 量化格式（核心创新）

**S3D8（signed 3D 8-bit）** 是一种**每参数 2.7 位**的量化格式：

- **编码方式**：每 **3 个权重共用 1 个字节（8 bits）**，其中低 5 位为共享的质心索引（32 个质心），高 3 位为每个权重独立的符号位。
- **量化公式**：去量化权重 $\tilde{W} \in \mathbb{R}^{n \times k}$ 表示为：

$$\tilde{W}_{ij} = \alpha_i \cdot s_{ij} \cdot C_{q_{\lfloor i/3 \rfloor, j}, \, i \bmod 3}$$

其中 $\alpha_i$ 为逐通道尺度（bfloat16），$s_{ij} \in \{-1, +1\}$ 为逐元素符号，$C \in \{0,\dots,127\}^{32 \times 3}$ 为共享质心表，$q$ 为质心索引。

- **质心构建**：在 QAT 前，利用 **Lloyd-Max 算法**配合 k-means++ 初始化，对逐通道归一化后权重的绝对值进行聚类，获得 32 个质心（对应 3 个维度，共 96 个码值）。使用**绝对值质心 + 符号位**的设计，相当于将 256 个码字表达为 32 个绝对质心在 8 个卦限中的反射，显著节省了查找表空间。
- **Arm CPU 高效解码设计**（三个关键设计选择）：
  1. **输出通道打包**：每个字节打包的是 3 个不同输出通道的权重，而非相邻输入权重，避免融合去量化-点积内核中复杂的对齐和填充逻辑。
  2. **融合符号查找**：利用 Arm CPU 的 64 项表查找指令（TBL），将符号位直接并入查找表索引，避免额外的符号处理指令。
  3. **位布局优化**：以 `[S2 XOR S0, S1, Q4..0, S0]` 的方式排列比特，使解码 48 个元素只需 **5 条 SIMD 逻辑指令 + 3 次表查找**（见 Listing 1/2 的汇编代码验证）。
- **量化流程**：QAT 过程中，质心保持冻结，仅更新通道尺度、量化索引和符号位。每个 3-向量被分配到 L2 距离最近的质心。

### 5. 主要结论与发现

#### 5.1 量化效果

- **S3D8 在 2.68 bits/参数时，平均任务性能为 0.661**，相对于原始 bfloat16 模型（0.744）仅有 0.083 的性能下降（Table 1）。
- 在相近模型尺寸下，S3D8 大幅优于其他格式：
  - INT（2.71 bits）：平均性能仅 0.347
  - student-t（2.71 bits）：平均性能 0.565
  - lloyd-max（2.59 bits）：平均性能 0.436

#### 5.2 流程对比结论

- **QAT 在低比特率下显著优于 GPTQ 和 Direct cast**。
- 在约 2.7 bits 时，S3D8 + GPTQ 达到 0.340 平均性能，而 INT + GPTQ 仅为 0.018；应用 QAT 后，S3D8 的平均性能提升至 0.661。
- 直接转换（Direct cast）在低于 3.5 bits 时造成严重模型退化。

#### 5.3 提示采样结论

- 采样提示（sampled prompting）在同等训练步数下显著优于固定提示，说明了**训练数据多样性对 QAT 下游泛化的关键作用**。

#### 5.4 推理性能结论（Table 2）

- **自回归生成（m=1）**：S3D8 显著优于 INT8——Pixel 8a 5核上 S3D8 达 33.8 GMAC/s vs INT8 的 26.5 GMAC/s；Graviton4 上 S3D8 达 1031 GMAC/s vs INT8 的 461 GMAC/s（**2.2 倍加速**）。
- **文本/图像预填充（m>1）**：S3D8 略慢于 INT8（计算受限场景下去量化开销无收益），但仍与 INT8 相当（如 Graviton4 上 6994 vs 7700 GMAC/s）。
- **端到端部署**：Pixel 8a 上 S3D8 达到 3.8 tokens/s（模型文件仅 3.73 GB，包含词表和元数据），参数读取带宽 12.5 GB/s，达到了设备峰值带宽（≈25 GB/s）的相当比例。Graviton4 上 S3D8 为 36.8 tokens/s vs INT8 的 26.4 tokens/s。

### 6. 优点（方法亮点）

- **完整且实用的三大模块设计**：合成数据管道、量化格式设计、Arm CPU 推理内核三者协同设计，形成了一个从压缩到部署的端到端闭环。
- **无需原始训练数据的 QAT 方案**：使用模型自身生成数据，突破了实际部署中数据不可得的约束，通用性强。
- **新颖的 S3D8 数值格式**：在 2.7 bits 的极低码率下，利用"绝对值质心 + 符号位"的思想，在格式表达能力与硬件解码效率之间取得了出色的平衡。**每个字节编码 3 个权重**的结构化设计配合 Arm TBL 指令仅需 5 条逻辑指令即完成解码。
- **软硬件协同设计（Hardware-Software Co-Design）**：量化格式围绕 Arm SIMD 解码路径量身定制，而非事后适配，使得内存带宽受限场景（自回归生成）获得超过 2 倍的实际加速。
- **严谨的对照实验**：所有格式基线使用相同的 QAT 流程，GPTQ 使用自定义的覆盖全模型（含视觉编码器）的实现，控制变量做得较好。
- **充分的工程细节**：附录提供了完整的提示模板、内核代码、反汇编验证、基准测试配置和方法论（bootstrapping 置信区间），可复现性强。

### 7. 不足与局限

- **模型覆盖单一**：所有实验仅验证了 Llama 3.2 11B Vision Instruct 一个模型，未在多模型（如 Gemma 3、Qwen3-VL 等）上验证方法的泛化性。不同 VLM 架构（如不同的视觉编码器、跨注意力设计）对极端量化的响应可能存在显著差异。
- **硬件适配受限**：S3D8 的解码方案依赖 Arm CPU 的 64 项 TBL 表查找指令；其他架构（如 x86、GPU、NPU）需要专门的内核开发，通用性受限。
- **评估范围偏窄**：仅使用 4 个 VQA 类基准（VQAv2、ChartQA、DocVQA、AI2D），未覆盖图像描述、视觉推理、多图理解、视频理解等更广泛的多模态能力；且仅使用固定 1024 样本子集，可能无法完全反映模型完整能力。
- **训练算力信息缺失**：未披露 GPU 数量/型号、总训练时间等关键资源指标，影响方法适用性评估。
- **保留高精度层无收益的结论有限**：实验仅尝试了 OP 和 VE 两个模块的 INT8 保留，更大范围的高精度层选择（如注意力层、特定深度层）未被探索。
- **最终产品质量仍落后于全精度**：S3D8 在部分任务上性能降幅明显（如 AI2D 从 0.631 降至 0.554，ChartQA 从 0.747 降至 0.648），对于高精度要求高的应用可能不可完全接受。
- **未与其他先进 QAT 方法对比**：附录中提及 LLM-QAT 等相关工作受限于多模态场景，但未直接与其他 VLM 量化方法（如 Q-VLM、MBQ、VLMQ）进行定量对比。
