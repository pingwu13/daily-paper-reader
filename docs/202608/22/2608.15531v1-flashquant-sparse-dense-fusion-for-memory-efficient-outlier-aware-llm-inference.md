## 摘要
低比特量化降低了大型语言模型（LLM）推理的内存占用和计算成本。然而，高幅度的异常值权重可能引起显著的量化误差，降低模型精度。异常值感知量化通过在保留异常值以高精度的同时量化其余权重来解决该问题，从而产生低比特稠密GEMM路径和高精度稀疏SpMM路径。现有实现在单独的GPU内核中执行这些路径，尽管它们共享激活和输出，这错失了算子内重用的机会，并导致冗余的全局内存访问。这种低效在内存受限的解码工作负载中尤为突出。我们提出FlashQuant，一种用于异常值感知W4A16解码的内容共享执行框架。FlashQuant将稠密GEMM和稀疏异常值SpMM路径融合到单个GPU内核中，使得异构计算之间能够在芯片上重用激活和输出瓦片。它引入了三种关键技术：稀疏-稠密瓦片化，它将异常值处理与稠密GEMM瓦片对齐；Tile-COO异常值编码，它实现了高效的稀疏访问并减少了共享内存存储体冲突；以及流水线调度，它使计算与数据移动重叠。实验表明，FlashQuant减少了异常值处理开销，相比cuBLAS BF16实现了$2.74\times - 4.18\times$的加速，相比最强的非融合异常值感知基线实现了高达$1.53\times$的加速。

## Abstract
Low-bit quantization reduces the memory footprint and computational cost of large language model (LLM) inference. However, high-magnitude outlier weights can induce substantial quantization errors and degrade model accuracy. Outlier-aware quantization addresses this issue by retaining outliers in high precision while quantizing the remaining weights, resulting in a low-bit dense GEMM path and a high-precision sparse SpMM path. Existing implementations execute these paths in separate GPU kernels, despite their shared activations and outputs, thereby missing opportunities for intra-operator reuse and incurring redundant global-memory accesses. This inefficiency is particularly pronounced in memory-bound decoding workloads. We propose FlashQuant, a content-sharing execution framework for outlier-aware W4A16 decoding. FlashQuant fuses the dense GEMM and sparse outlier SpMM paths into a single GPU kernel, enabling on-chip reuse of activation and output tiles across heterogeneous computations. It introduces three key techniques: sparse-dense tiling, which aligns outlier processing with dense GEMM tiles; Tile-COO outlier encoding, which enables efficient sparse access and reduces shared-memory bank conflicts; and pipelined scheduling, which overlaps computation with data movement. Experiments show that FlashQuant reduces outlier-processing overhead, achieving $2.74\times - 4.18\times$ speedup over cuBLAS BF16 and up to $1.53\times$ speedup over the strongest unfused outlier-aware baseline.

## 1. 论文的核心问题与整体含义（研究动机和背景）

- **背景**：大型语言模型（LLM）参数规模不断增长，推理时的内存占用和计算成本极高。例如 Qwen3-235B 在 BF16 精度下需要超过 470GB 内存，超出主流 GPU（如 A100）的内存容量。
- **已有方案**：低比特权重量化（如 INT4）能显著降低内存占用和带宽成本，但高幅度异常值权重在量化时会产生严重的重建误差，损害模型精度。
- **异常值感知量化**：保留少量高精度异常值（如 BF16），量化其余权重，从而在精度与压缩率间取得更好的平衡。例如，LLaMA3-8B 在 INT4 量化下保留 1% 异常值，可将 WikiText2 困惑度从 6.896 降至 5.979。
- **核心问题**：异常值感知量化将矩阵乘法分解为两部分：
  - 低比特稠密 GEMM 路径（量化权重）
  - 高精度稀疏 SpMM 路径（异常值权重）
  
  现有系统使用**两个独立的 GPU 内核**分别执行这两条路径，导致：
  - 两个内核重复从全局内存加载相同的激活矩阵 X
  - 各自独立写入部分输出，产生冗余内存流量
  - 在内存受限的解码阶段（batch size 小、带宽瓶颈突出），即使少量异常值也会带来不成比例的延迟开销
- **论文含义**：FlashQuant 通过**内容共享融合执行**——将稠密 GEMM 与稀疏 SpMM 融合为单一 GPU 内核，在同一分块执行空间内协同调度两条异构计算路径，在片上复用激活和输出数据，从根本上消除冗余全局内存访问，实现更高效的异常值感知推理。

## 2. 论文提出的方法论

### 2.1 核心思想

FlashQuant 将低比特稠密 GEMM 和高精度稀疏 SpMM 融合进单个 GPU 内核，使两条路径共享激活瓦片（activation tiles）并在片上累积部分输出，而非分开执行导致重复访存。

### 2.2 关键技术一：稀疏-稠密分块（Sparse-Dense Tiling）

在 **CTA、Warp、Thread** 三个层级建立稠密与稀疏路径的瓦片对应关系：

- **CTA 级别**：将稠密和稀疏计算映射到同一输出瓦片，激活瓦片只加载一次进共享内存，被两条路径复用。采用 Stream-K 策略将聚合 MAC 迭代空间分配到持久 CTA，改善负载均衡。
- **Warp 级别**：稠密路径使用 Tensor Core MMA 指令，扩展 Sliced-K 并行；稀疏路径使用 CUDA Core，分配互不重叠的输出列集合以避免写冲突，同时可额外分配 warp 缓解访存延迟。
- **Thread 级别**：稠密路径按 Tensor Core MMA 布局映射线程；稀疏路径将共享内存激活按 8 元素 swizzle（16字节/4 bank）存储，并将输出列划分为桶（bucket），每个桶由一组线程处理，减少 bank 冲突。

### 2.3 关键技术二：Tile-COO 异常值编码

提出面向瓦片局部性的新型稀疏格式 **Tile-COO**，满足四个要求：
1. 异常值条目与 GEMM 瓦片边界对齐
2. 稀疏元数据和值的向量化访问
3. 与共享内存激活布局直接兼容
4. 不规则分布下的负载均衡

Tile-COO 结构包括三个数组：
- `tile_indptr`：记录每个瓦片的起始偏移（UINT32）
- `bucket_info`：记录桶的偏移和元素数（UINT16）
- `packed_outliers`：打包存储行索引、列索引和异常值，每 4 个元素一组，行/列索引用 UINT8、值用 BF16

此外，采用**两阶段稀疏重排序**：
- **列重排序**：按非零数量降序排序列，用贪心堆调度分配到桶，平衡负载
- **元素重排序**：根据行索引的 bank 组（gid = (k/2) % 4）按桶依赖的循环顺序重排元素，交错不同子 warp 的访问，减少共享内存 bank 冲突（示例从 4 次冲突降至 1 次）

### 2.4 关键技术三：流水线调度（Pipelined Execution）

多阶段流水线 + 双缓冲重叠数据移动和计算，四个阶段：
1. 从全局内存加载数据（异步拷贝到共享内存）
2. 寄存器暂存数据
3. 反量化和异常值解码
4. Tensor Core 和 CUDA Core 计算

### 2.5 核心公式

\[
Y = X \cdot W \approx X \cdot \text{dequant}(W_Q) + X \cdot W_O
\]

其中 \(W_Q\) 为低比特稠密权重矩阵，\(W_O\) 为稀疏高精度异常值矩阵。
