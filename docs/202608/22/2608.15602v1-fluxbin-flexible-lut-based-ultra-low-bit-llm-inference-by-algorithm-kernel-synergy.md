## 摘要
尽管二值量化在理论上承诺为大型语言模型（LLM）带来极致的压缩与加速，但现有研究往往忽视了专用硬件内核的必要性，因而由于持续依赖昂贵的浮点运算或运行时反量化开销，未能充分发挥全部加速潜力。为弥合这一差距，我们提出了FluxBin（基于二值基底的灵活查找表超低位宽执行），一种算法-内核协同设计，将训练后量化与高度优化的CUDA内核相结合。在算法层面，我们引入了解耦行列二值分解以增强表示能力，同时保持硬件效率，并辅以Hessian引导的显著性感知混合基底以保留关键信息。在内核层面，我们实现了一种带有尺度融合的查找表构建方法以减少浮点运算，其特征是虚拟列映射，可将不规则、稀疏且显著的矩阵转化为稠密执行。大量评估表明，FluxBin在不同模型架构上实现了高达5.92倍的加速和10.19倍的能耗节省，同时提供了与重度微调方法相当的精度。这有效地使得70B规模模型能够在单个A100 GPU上部署，内存减少4倍。代码可在https://github.com/nicyyyy/FluxBin获取。

## Abstract
While binary quantization theoretically promises extreme compression and acceleration for Large Language Models (LLMs), existing research often overlooks the necessity of specialized hardware kernels, thus failing to unleash the full acceleration potential due to persistent reliance on expensive floating-point arithmetic or runtime dequantization overheads. To bridge this gap, we propose FluxBin (\textbf{F}lexible \textbf{L}UT-based \textbf{U}ltra-low-bit e\textbf{X}ecution with \textbf{Bin}ary bases), an algorithm-kernel co-design that synergizes post-training quantization with a highly optimized CUDA kernel. Algorithmically, we introduce Decoupled Row-Column Binary Decomposition to enhance representational capacity while maintaining hardware efficiency, complemented by a Hessian-guided saliency-aware hybrid bases that preserve critical information. At the kernel level, we implement a Lookup Table Building Approach with Scale Fusion to reduce floating-point arithmetic, featuring a Virtual Columnar Mapping that transforms irregular, sparse, and salient matrices into dense execution. Extensive evaluations demonstrate FluxBin achieves up to $5.92\times$ speedup and $10.19\times$ energy savings across diverse model architectures, delivering comparable accuracy to heavily fine-tuned methods. This effectively enables the deployment of 70B-scale models on one single A100 GPU with a $4\times$ memory reduction. Code is available at https://github.com/nicyyyy/FluxBin.

# FluxBin 论文总结

## 1. 核心问题与整体含义
- **背景**：大型语言模型（LLM）规模庞大，训练后量化（PTQ）是主流压缩方案，而二值量化（1-bit）理论上可将压缩和加速推向极限。
- **核心问题**：现有二值/超低位宽量化方法大多只优化算法精度，实际推理时仍依赖 FP16 反量化或浮点运算，无法发挥位运算与加法运算的硬件潜力；同时，细粒度显著性保留与硬件执行效率之间存在矛盾，现有低比特 CUDA 内核也不够高效，导致“理论压缩”难以转化为“真实加速”。
- **整体含义**：FluxBin 提出算法-内核协同设计（algorithm-kernel co-design），将 PTQ 量化方法与其专用 LUT 内核深度绑定，用查表替代乘法，把超低位宽模型转化为实际的吞吐提升、能耗降低和内存节省。

## 2. 方法论
- **算法层面**：
  - **解耦行列二值分解**：将权重矩阵近似为多个二值基的线性组合，每个基带有行缩放向量和列缩放向量，即 \(\hat{W}^{(k)} = (\alpha_r^{(k)} \alpha_c^{(k)\top}) \odot B^{(k)}\)；通过交替最小化求解行/列缩放，并通过枚举 \(2^{K_b}\) 种符号组合联合优化二值基。
  - **Hessian 引导的显著性感知混合基**：借助 OBQ 框架计算列级显著性（基于权重平方与 Hessian 逆对角线），在每个分组内选出最显著的若干列，构造掩码；最终权重 = 全局二值基近似 + 仅作用于显著列的残差精修二值基，兼顾精度与结构化执行。
  - **纯 PTQ**：无需微调或蒸馏，算法集成在 GPTQ 块式重建流程中，利用 Hessian 逆进行误差补偿。
- **内核层面**：
  - **LUT 构建与尺度融合（LUT-BSF）**：把输入子向量与列缩放预先融合，构建 \(2^\mu\) 项查找表；推理时用二值权重模式作为地址直接读取部分和，去除主循环中的浮点运算。
  - **虚拟列映射（VCM）**：将逻辑稀疏的显著列重映射为物理稠密矩阵，通过索引翻译层在运行时收集激活和缩放，使混合精度分支复用同一个稠密内核，避免不规则访存。
  - **矩阵分块与共享内存复用**：按 \(M_{\text{tile}} \times K_{\text{tile}}\) 分块，块内线程共享 LUT，并配套线程块级归约与行缩放。

- **加速来源**：权重压缩降低 HBM 流量；LUT 使每 \(\mu\) 个权重对应的乘加变为一次共享内存查表（约 \(\mu/K_b\) 倍复杂度降低）；用 SRAM 查表替换 ALU 密集的反量化指令，且这些优势与 batch size 基本无关。

## 7. 优点
- 算法与内核深度协同，真正把二值基的“乘法免费”潜力落地为端到端加速。
- 行列解耦缩放比纯行缩放更能捕捉权重各向异性，为低比特量化提供更强表示能力。
- Hessian 引导的显著混合基以极小额外存储（约 6.25% 列）换取显著精度提升。
- 虚拟列映射将稀疏显著列转为稠密运算，统一内核、降低访存开销，工程实现巧妙。
- 理论分析完整：推导最优缩放、二值基分配、LUT 复杂度、存储位宽与共享内存占用。
- 开源代码，且为纯 PTQ，实际部署成本低。

## 8. 不足与局限
- **共享内存瓶颈**：LUT 大小随子向量长度 \(\mu\) 指数增长（\(2^\mu\)），在共享内存较小的硬件上必须降低 \(\mu\) 或 batch，可能削弱加速效果。
- **精度天花板**：作为纯 PTQ，相比基于大量迭代微调/蒸馏的方法仍存在微小精度差距；在部分敏感模型上低于 3-bit 基线。
- **硬件普适性

硬件普适性：LUT 与虚拟列映射的优化深度绑定 CUDA 与 NVIDIA GPU 共享内存架构，对共享内存容量较小或动态共享内存支持受限的硬件（如某些移动 GPU、FPGA、TPU）难以直接移植；CUDA Graphs 依赖特性使框架调度开销消除仅限 NVIDIA 平台，跨平台部署需重新设计内核。

- **额外开销与复杂度**：VCM 索引翻译层在每次前向传播中引入间接寻址和收集/分散操作，虽然换来了规则访存，但增加了内核复杂性与潜在分支开销；混合基中显著列与非显著列的长度不齐，需要动态划分，可能造成部分线程束利用率下降。

- **分组大小与子向量超参数敏感**：最优分组大小（g128）和子向量长度 μ 依赖具体模型和硬件，论文中虽进行了消融，但未提供自动选择策略；部署到新模型时需手动搜索，增加了使用成本。
