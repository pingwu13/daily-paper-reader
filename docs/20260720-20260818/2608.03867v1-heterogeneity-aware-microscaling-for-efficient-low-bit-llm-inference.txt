Low-Bit LLM Inference

Abstract—Microscaling (MX) is now the standard for low-bit
large language model (LLM) inference. Its 4-bit form MXFP4
still loses substantial accuracy, because existing MX formats fix
either the element format or the precision-recovery scheme across
blocks, and thus capture only limited quantization heterogeneity.
Quantization heterogeneity appears at two levels: 1) across
blocks, the preferred element format and precision-recovery
scheme vary; 2) across operands, weights and activations require
different encoding. We introduce AdaMX (Adaptive Microscal-
ing), a heterogeneity-aware format and accelerator. It selects the
precision-recovery scheme per block and the representation per
operand, at no increase in equivalent bit width (EBW). One
design covers two block sizes, giving a higher-accuracy operating
point and a lower-EBW operating point that saves storage.
We implement a 22nm FD-SOI AI accelerator prototype with
the proposed decoder, computing unit, and quantization logic.
Against an otherwise identical MXFP4 accelerator with FP4-
only multipliers, AdaMX adds about 1% system energy. At the
lower-EBW point, AdaMX stays more accurate than the baseline
while lowering both memory footprint and energy. Across LLMs
from 3B to 70B, AdaMX removes 83% of the MXFP4 accuracy
loss on commonsense and 82% on MMLU, and 43% and 27% of
the NVFP4 loss. AdaMX also generalizes to multimodal models.
On Gemma-4 12B, it leads MXFP4 on all four vision-language
benchmarks and keeps up to 96% of FP16 accuracy.
I. INTRODUCTION
LLM inference is memory-bound. Recent models reach
hundreds of billions of parameters [2], [12], [43], so reading
their weights from off-chip memory dominates both latency
and energy, with each off-chip access far costlier than an
arithmetic operation [22]. Low-bit quantization shrinks the bits
moved per weight and activation and is the main lever for
efficient LLM inference; it also lets a fixed memory budget
hold a larger model.
The Microscaling (MX) format has become the industry
standard for this purpose. It is standardized by the Open Com-
pute Project [42] and natively supported in recent accelerators
such as NVIDIA Blackwell [41], AMD Instinct MI350 [1],
Microsoft Maia 100 [59], and Meta MTIA [38]. MX partitions
a tensor into small blocks and gives each block a single E8M0
scale, a power-of-two format with 8 exponent (E) bits and
0 mantissa (M) bits. Its 4-bit form MXFP4 saves the most
memory, but at this width the power-of-two scale is too coarse,
and MXFP4 degrades sharply in both perplexity (PPL) and
downstream accuracy [9], [49].
Recent formats narrow this gap in two ways (Figure 1).

II. BACKGROUND AND MOTIVATION
A. Microscaling and Its 4-bit Formats
Post-training quantization maps high-precision tensors to
low-bit representations, cutting the memory and compute of
LLM inference [3], [13]–[16], [29], [30], [32], [51], [55],
[58], [62], [66]. Block-wise quantization, which shares one
scale across 16–128 elements, has become the prevailing
choice [19], [24], [25], [31], [34], [41], [42], [48]. MX
is widely studied and deployed [9], [10], [25], [28], [31],
[54], [56], [65]. For a block {xi} and an element format
whose largest power of two is P, the shared exponent is
S = 2⌊log2(maxi |xi|/P )⌋[49]. Alternative scale-rounding rules
exist [9], [39], [60]; Section III-C2 evaluates the effect of this
rounding choice.
Beyond the shared scale, the element type provides another
design dimension in 4-bit MX formats. FP4 (E2M1) uses a 1-
bit sign, a 2-bit exponent, and a 1-bit mantissa, forming a non-
uniform grid that is denser near zero and better captures values
spanning a wide dynamic range. In contrast, INT4 uses a 1-
bit sign and a 3-bit magnitude, providing a uniform grid with
finer resolution over a fixed range. Chen et al. systematically
analyze the accuracy trade-off between INT and FP under
fine-grained MX quantization and find that FP4 generally
outperforms INT4 at 4-bit precision [6]. We revisit this tensor-
level conclusion at the block level in Section II-C.
B. Metadata-Augmented MX Formats
To recover the accuracy MXFP4 loses to its coarse scale,
recent designs augment each MX block with metadata [25],
[26], [31], [46]. Table I compares them along two axes: the
granularity of the metadata (element, subgroup, or block) and
its content (extra mantissa bits, extra exponent bits, or a format
index). Two techniques are commonly used. Block-maximum
mantissa extension adds mantissa bits to the block’s largest
element, which dominates MXFP4 error [31]. Because this
element’s exponent is fixed at the format’s maximum, its
exponent bits carry no information and can be reused as
mantissa bits, promoting it from FP4 to FP6 at no extra block
storage. MX+ records the element’s position with a 5-bit index,
while M2XFP clamps the FP6 result to a 4-value neighborhood
with 2 bits [25]. Scale refinement instead adds mantissa bits
to the shared scale, thereby reducing quantization error across
all block elements. Because the E8M0 scale jumps in factors
of two, up to half of a block’s range goes unused when its
maximum falls between two bins; NVFP4 replaces E8M0 with
an E4M3 scale, adding 3 mantissa bits [41], and M2XFP
adjusts the sub-block scale with 2 bits [25]. Figure 4 illustrates
both mechanisms, and Section III details how AdaMX applies
them.

9B [47]) and identify two forms of heterogeneity and show that
the MX exponent field provides sufficient capacity to encode
them.
Weight-side block-level heterogeneity. Figure 2 reveals
two orthogonal forms of block-level heterogeneity in weights.

consistently favor FP4 over INT4 at the tensor level [6], [58].

with a single deterministic rounding (Section III-C2), then
extends the block maximum online. Online block-maximum
promotion requires additional metadata: storing a per-block
index to locate the element costs 5 bits [31], which exceeds
the available metadata budget, while appending mantissa bits
to the stored FP4 value [25] succeeds only when the higher-

not, prior work clamps to a neighborhood of the stored value
and loses precision [25]. AdaMX instead encodes the block
maximum losslessly (Section III-C3).

III. ADAMX DESIGN
Section II-C established that the 8-bit MX scale field is
overprovisioned for LLM workloads. This section presents
AdaMX, a format family that reclaims these spare bits as per-
block metadata. We first introduce the two-level scale structure
that enables narrower per-block exponents while preserving
full dynamic range (Section III-A), then detail the weight-
side format with its 2-bit type routing across four format-
enhancement combinations (Section III-B), followed by the
activation-side format, which combines a 1-bit scale refine-
ment with a lossless FP6 block-max extension (Section III-C).
The AdaMX family provides two operating points that share
identical encoding and hardware but differ in block size:
AdaMX-16 at 4.5 bits/element (block size 16) and AdaMX-32
at 4.25 bits/element (block size 32).
A. Two-Level Scale with Anchored Bias
Both AdaMX formats replace the 8-bit E8M0 shared expo-
nent with a narrower per-block exponent anchored by a coarser
bias. The effective scale for each block is
S = 2 bbias + eblock,
(1)
where bbias is an 8-bit integer set at a coarser granularity and
eblock is the per-block residual exponent in E4. Activations
refine this scale with a 1-bit mantissa.
Weights. bbias is set to the minimum block exponent within
each output channel, making every residual eblock nonnegative;
the per-channel range stays inside E4’s 0–15.
Activations. bbias is set per token, computed online by
tracking the minimum of the per-block scale exponents as they
are produced by the encoder, with eblock the unsigned residual.

Format axis. Section II-C established that FP4 and INT4
each suit roughly half of all weight blocks within a tensor:
the FP4 grid favors blocks where most values cluster near
zero with a few large outliers, while INT4’s uniform grid
favors flatter magnitude distributions. T2 therefore routes the
format choice per-block (Figure 4(a)), capturing diversity that
tensor-level or layer-level assignment cannot. The two grids
allocate quantization levels differently across the representable
range: FP4 allocates more levels near zero and fewer levels
at large magnitudes, whereas INT4 distributes its levels uni-
formly. Blocks concentrated near zero therefore tend to incur
lower error under FP4, whereas blocks with flatter magnitude
distributions tend to favor INT4.

is reconstructed at 6-bit precision from its 4-bit value and the
2-bit Mt2 index; the remaining k−1 elements decode at 4-
bit precision. The decoder identifies this element by argmax
over the decoded 4-bit magnitudes, the same rule the encoder
used, with ties broken by the lowest index. No position index
is stored, so Mt2 carries only the mantissa extension.

C. Activation Format: E4M1Mt2N1
1) Bit Layout and Design Rationale: The activation-
side metadata byte consists of four fields (Figure 1): E4
(4 bits), M1 (1 bit), Mt2 (2 bits), and N1 (1 bit). E4 and
M1 form the E4M1 block scale: E4 is the residual exponent
relative to the per-token bias, and M1 is a 1-bit scale mantissa
(Section III-C2). Mt2 extends the block-maximum element
from FP4 to FP6 (E2M3) precision. N1 selects between two
encoding neighborhoods that together cover every FP6 round-
to-nearest target (Section III-C3).
The activation side omits the T2 type selector for two
reasons: activation outliers favor FP4 over INT4 [6], and online
quantization rules out the costly per-block scale search. M1
thus refines the scale with a single rounding (Section III-C2),
and the freed T2 bits become M1 and N1.
2) Scale Refinement and Rounding: The M1 mantissa
turns the activation scale into E4M1, S = 2 bbias+eblock · m
with m ∈{1, 1.5}, chosen to map the block maximum near
FP4’s max-norm vmax = 6.
S requires a rounding policy. The original MX format
rounds the shared scale down (floor) [42], [49]; later works
use ceiling rounding to lower clipping [39], [60] or adaptive
block scaling [9]. AdaMX rounds to nearest, co-designed with
the FP6 block-max extension. The ideal scale S∗would land
the block maximum exactly on vmax = 6, but M1 offers only
{1, 1.5} per octave, so the encoder must round S∗to a nearby
grid scale S. Writing β = S∗/S for the ratio of the ideal
scale to the chosen scale, the block maximum lands at 6β
instead (Figure 6): under-scaling (β > 1) overshoots 6, and
over-scaling (β < 1) falls short. Round’s worst ratio is the
midpoint 1.25 of the {1, 1.5} grid, so the block maximum
reaches at most 6 × 1.25 = 7.5, exactly FP6’s max-norm,
which N1 recovers with no clipping (Section III-C3). Floor’s
worst ratio is 1.5, reaching 6 × 1.5 = 9, which clips even in
FP6; ceil holds the maximum below 6 and leaves the FP6 head-
room unused. Only round-to-nearest bounds the worst-case
scaled block maximum at the maximum representable FP6
5


value, demonstrating that the scale grid and block-maximum
extension are co-designed. With AdaMX-16 otherwise fixed,
round gives the lowest perplexity: 6.86, versus 6.90 for ceil
and 7.08 for floor on Llama-3.1-8B, and 8.80 versus 8.90 and
9.07 on Qwen2.5-3B.
Scale computation requires no division. Write the block
maximum as maxi |xi| = ma 2ea with ma ∈[1, 2). FP4’s
largest representable value is vmax = 6 = 1.5 · 22. The ideal

factor 2 ea−2 is an exact power of two and only sets the
exponent. Rounding the ideal scale onto the {1, 1.5}×2Z grid
thus reduces to rounding the mantissa factor (ma/1.5) onto
the same grid. Since ma ∈[1, 2), this factor spans [2/3, 4/3).

IV. ARCHITECTURE
This section describes the AdaMX hardware, which inte-
grates AdaMX into an output-stationary systolic array (SA)
with lightweight modifications. A fixed 32-lane MAC mi-
croarchitecture supports runtime-selectable block sizes K ∈
{16, 32}, so one design serves both operating points. Sec-
tion V reports the corresponding power, performance, and area
results.
A. Hardware Overview
Figure 9 presents the AdaMX architecture, which uses
an M×N output-stationary systolic array (SA). Each PE
computes a 2×2 output tile with four fixed 32-lane dot-product
MAC blocks, each with a private FP32 accumulator. The
four MACs share two activation-row and two weight-column
operand registers, halving the operand-register count per MAC
relative to four single-MAC tiles.

places one decoder per row and the weight decoder array
(WDA) one per column. Each decoder consumes one encoded
operand per cycle and broadcasts 32 decoded operands along
its row or column (Section IV-B). For an M×N array this
placement reduces decoder replication from MN instances
to M+N. Each MAC pairs a 32-lane base path, built from
asymmetric 2-by-3-bit element multipliers, with a per-block
correction sidepath for block-maximum mantissa extension,

D. Activation Quantization Unit
The activation quantization unit re-encodes the FP32 outputs
into E4M1Mt2N1 blocks for the next layer (Figure 12). A
running maximum over the streaming FP32 outputs determines
the block scale. The Scale Finder reads the amax leading bits
(Equation (2)) with two comparators and a mux, giving the
E4M1 exponent E and M1 mantissa. FP4 Quant maps every
element to FP4 by round-to-nearest. The block-maximum
index then comes from the quantized FP4 magnitudes, with
ties resolved toward the lowest index so the decoder locates the
same element. FP6 Quant re-quantizes that element, encoding
its offset as ∆→(Mt2, N1) (Section III-C3). Each block’s
absolute 8-bit exponent E is buffered in the scale cache while
a running min over the token tracks the per-token bias bbias.
Once the token completes, the cache drains, and each stored
E is converted during cache draining to the 4-bit residual
eblock = E −bbias (Section III-A) as its final E4M1Mt2N1
block is written. The pipeline is streaming and overlaps with
SA computation without stalling the array.

tor is removed by subtracting E from the element expo-

maximum in [5.0, 7.5), FP6 Quant resolves its six reachable
codes with only five comparisons. The M1 scale refinement
thus adds no arithmetic on the encode path.
V. EVALUATION
A. Methodology
Models and benchmarks. We evaluate AdaMX on four
LLMs from two families, spanning parameter scales from 3B
to 70B: Llama-3.1-8B and Llama-3.1-70B [37], and Qwen2.5-
3B and Qwen2.5-14B [61], together with the multimodal
Gemma-4 12B [18]. We report WikiText-2 perplexity [36] with
a sliding window at context length and stride of 2048 [16],
[33], and zero-shot accuracy with lm-evaluation-harness [17]
on six commonsense tasks: ARC-Challenge [8], HellaSwag
[64], PIQA [5], WinoGrande [50], BoolQ [7], and Common-
senseQA [53]. We also report 5-shot MMLU [21] across its
STEM, humanities, social sciences, and other categories. For
KV-cache quantization, we evaluate W4A4KV4 inference on
Llama-3.1-8B using RULER [23] at context lengths of 8K and
32K.
Quantization. We apply AdaMX to both weights and
activations, keeping the embedding layer in FP16. At block
size 16, MXFP4 and AdaMX-16 both use 4 element bits and
an 8-bit shared field, giving 4.5 EBW; AdaMX redistributes
that field, encoding weights as E4Mt2T2 and activations as
E4M1Mt2N1 (Section III-A), while doubling the block to 32
gives 4.25 EBW.

Downstream accuracy. Table III reports zero-shot com-

four categories, where higher is better. AdaMX-16 retains
at least 97 percent of the FP16 commonsense average on
every model, and at least 95 percent of the MMLU category

Long-context KV cache. We also measure the performance
of the KV cache quantization in long-context scenarios. Each
K/V entry is written once and reused by all subsequent
decoding steps, giving the KV cache a read-mostly reuse
pattern closer to weights than to transient activations. We
therefore encode it with AdaMX’s weight-side format and
apply the same per-block format-selection rule. Although this
per-block selection incurs a one-time encoding cost when the
block is written, the cost is amortized over its repeated reads in
subsequent decoding steps. We evaluate W4A4KV4 inference
on Llama-3.1-8B using RULER [23] at context lengths of 8K
and 32K (Table VI). At the matched 4.5 EBW point, AdaMX-
16 exceeds NVFP4 by 2.4 points at 8K, and the margin widens
to 6.1 points at 32K on the 13-task average. AdaMX-16 ranks
first among the low-bit formats on five of the six task groups
at each length. At 4.25 EBW, AdaMX-32 also outperforms
MXFP4 by 36.8 and 41.1 points at 8K and 32K, respectively.
C. Hardware Evaluation
Area and power. Table VII reports area and power for
the AdaMX accelerator and its processing element, with
MXFP4 as the baseline. Both designs use a 2×2 MAC PE,
contain the same number of multipliers (8192), and share
an identical 864 KB SRAM buffer, so the comparison is
matched in throughput and memory. The MXFP4 array totals
2.10 mm2 and the AdaMX array 2.16 mm2, a 3.2% increase.
This increase comes from the block-max extension and scale
refinement that AdaMX adds in each PE. The power follows
the same pattern: at 500 MHz the AdaMX array draws
482 mW and the MXFP4 array 466 mW, a 3.5% increase. The
AdaMX MAC array sustains a peak 8.19 TOPS at 500 MHz,
corresponding to a compute efficiency of 17.1 TOPS/W.
Energy breakdown. We model end-to-end inference with
SCALE-Sim [45]. The on-chip buffer is 864 KB and the clock
is 500 MHz. Per-MAC energy is obtained from PrimeTime
power analysis, SRAM energy from Accelergy [57] and data
sheets, and DRAM energy from CACTI [4]. All four formats
share the array size, clock, and buffer, so they run at identical
throughput. The workload is decode at batch 8, 32, and 128,
over the 2048-token context. Figure 13 reports decode energy
for four models, normalized to the MXFP4 block-16 total of
each model. External memory dominates at 61 to 94 percent
of system energy. AdaMX-16 raises the per-MAC energy by

to system energy. This modest energy overhead accompanies
the substantial accuracy improvements reported in Table IV
and Table III. Relative to MXFP4 at block size 16, AdaMX-

trades some accuracy relative to AdaMX-16, but it is still more
accurate than MXFP4 at the same 4.25 EBW. This reduction
follows from the lower EBW: block size 32 spends 4.25 bits
per element rather than 4.5 at block size 16, so each weight
access transfers fewer bits. The block-size saving therefore

VI. CONCLUSION
Quantization heterogeneity arises across both blocks and
operands. We introduce AdaMX, which repurposes MX’s over-
provisioned exponent bits as operand-specialized metadata:
weights route each block among four format-enhancement
modes, while activations use round-to-nearest E4M1 scaling
with a lossless FP6 block-maximum extension. The same
weight-oriented format is further extended to KV-cache quan-
tization. We design a 22-nm FD-SOI accelerator that supports
block sizes 16 and 32 on a unified datapath while efficiently
decoding the proposed metadata. Across LLMs from 3B
to 70B and the Gemma-4 12B multimodal model, AdaMX
substantially outperforms MXFP4 and exceeds NVFP4 at
comparable bit budgets. AdaMX-16 adds at most 1.1% system
energy, while AdaMX-32 reduces it by 2.9–5.2%. These
results demonstrate that lightweight, operand-aware metadata
can improve the accuracy–efficiency tradeoff of 4-bit mi-
croscaling with only modest additional hardware complexity.
