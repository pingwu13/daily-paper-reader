## 摘要
超低比特语言模型可以减少存储和内存带宽，但名义上的“1.58比特”标签并不能完全描述存储表示、保留能力或运行时行为。我们研究了对一个经过指令调优的40亿参数模型Qwen进行端到端后训练转换，使用了KOTMS旋转、E2M-ATQ三值化以及来自TWLA的GPTQ风格误差补偿。实验仅针对权重：激活保持16位精度，因此省略了ILA-AMP。我们评估了有效比特计算、任务能力保留、困惑度、校准敏感性、检查点组成和部署行为。最终的转换对量化线性权重使用每权重1.641有效比特，目标覆盖模型参数的81.62%。在十项评分能力比较中，准确率从64.5%降至54.7%。退化不均匀：BoolQ保留了84.6%的随机校正教师性能，而ARC-Challenge仅保留43.8%。困惑度在WikiText-2上从13.639升至18.748，在PTB上从24.700升至31.992，在C4上从19.831升至28.966。后续的打包运行保留了三值平面和缩放，将报告模型大小从8.29 GiB降至3.96 GiB，困惑度基本不变。另一次第三方打包尝试有损，因此被排除在主要工件声明之外。打包后的工件尚未进行端到端的任务准确性或生成吞吐量基准测试。初步的Triton GEMV微基准测试显示，在一种测试形状下比FP16 cuBLAS慢4.6倍。因此，我们不声称仅压缩就能带来更快的推理。

## Abstract
Ultra-low-bit language models can reduce storage and memory bandwidth, but a nominal "1.58-bit" label does not fully describe the stored representation, retained capability, or runtime behavior.   We study an end-to-end post-training conversion of Qwen, an instruction-tuned 4B-parameter model, using KOTMS rotation, E2M-ATQ ternarization, and GPTQ-style error compensation from TWLA. The experiment is weight-only: activations remain at 16-bit precision, so ILA-AMP is omitted. We evaluate effective bit accounting, task capability retention, perplexity, calibration sensitivity, checkpoint composition, and deployment behavior.   The final conversion uses 1.641 effective bits per weight for quantized linear weights, with 81.62% of model parameters targeted. Across ten scored capability comparisons, accuracy falls from 64.5% to 54.7%. Degradation is uneven: BoolQ retains 84.6% chance-corrected teacher performance, while ARC-Challenge retains 43.8%. Perplexity rises from 13.639 to 18.748 on WikiText-2, 24.700 to 31.992 on PTB, and 19.831 to 28.966 on C4.   A subsequent packing run preserves the ternary planes and scales, reducing reported model size from 8.29 GiB to 3.96 GiB with essentially unchanged perplexity. A separate third-party packing attempt was lossy and is excluded from the primary artifact claim. The packed artifact has not been benchmarked end-to-end for task accuracy or generation throughput. A preliminary Triton GEMV microbenchmark is 4.6x slower than FP16 cuBLAS on one tested shape. We therefore do not claim that compression alone yields faster inference.

- **核心问题**：名义上的“1.58-bit”标签无法反映模型实际存储的表示、保留了多少预训练能力，以及推理时的真实行为。论文主张应将“量化”拆分为四个独立且可分别测量的子问题：
  1. **能力（Capability）**：哪些下游行为在转换后幸存？
  2. **表示（Representation）**：计入自适应平面与元数据后，有效比特预算是多少？
  3. **存储（Storage）**：实际的工件（artifact）而非伪量化的 FP16 检查点，到底压缩了多少？
  4. **执行（Execution）**：更紧凑的表示是否真的能提升推理速度？
- **研究背景**：超低位语言模型可降低持久存储、内存带宽和硬件资源需求，但在“表示—能力—执行”三个维度上，真正的成本与效果常常被名义比特率掩盖。论文强调：压缩不等于加速，量化不等于序列化，能力保留不是均匀的。
- **整体含义**：这项研究是对一个 4B 预训练模型在“无重训练”前提下的后端量化转换的系统性实证刻画，旨在回答“压缩后的模型还能用吗、哪里不能用、是否真正变小了、是否能跑得更快”这四个实际工程问题。

## 2. 方法论：核心思想、关键技术细节与流程

- **整体管线**：FP16 Qwen3-4B → KOTMS → E2M-ATQ → GPTQ 补偿 → W1.58A16。
- **权重量化、激活保持 16 位**：实验有意仅量化权重（weight-only），激活保持 16 位（A16），因此跳过了 ILA-AMP 激活量化组件。
- **KOTMS 旋转**：使用结构化正交矩阵将权重空间变换到“对三值友好”的基方向：
  \[
  W' = WR,\quad R^\top R = I
  \]
  推理时改为对激活施加等效旋转。正交变换在精确算术下保持范数，引入的 FP16 舍入噪声可忽略（先前记录显示困惑度仅从 8.7998 变为 8.8003）。旋转矩阵本身是额外的连续值参数，会计入表示开销。
- **E2M-ATQ（二阶非对称残差三值化）**：
  - 对掩码权重块先计算行级偏移 \(\mu\)，得到去均值矩阵 \(W_c = W - \mu\)；
  - 用阈值 \(\Delta = 0.75 \cdot \text{rowmean}(|W_c|)\) 将每个元素映射为 +1/−1/0 三值支持；
  - 第一条三值平面 \(\alpha_0 T_0\) 通过最小化平方重建误差确定缩放；
  - 对残差再做一轮三值化，得到第二条平面 \(\alpha_1 T_1\)；
  - 重建权重为 \(\hat{W} = (\mu + \alpha_0 T_0 + \alpha_1 T_1) \odot M\)，其中 \(M\) 是显著性掩码；
  - 15 轮交替精化迭代固定三值支持、重新求解 \(\mu, \alpha_0, \alpha_1\)。
  - 由于 \(\mu \neq 0\)，重建浮点张量中确切“零”很少见；这意味着存储的浮点重建看起来“非三值”，但底层离散支持确是三值的。
- **显著性掩码（Salience Masks）与有效比特计算**：
  - GPTQ 封装器将每个矩阵按 Hessian 显著性分为 4 个不相交掩码，配置为 orders = [2,2,1,1]，即两个高显著性掩码用两条三值平面，其余用一条；
  - 在记录层上，掩码覆盖率分别为 0.5%、3.1%、10.0%、86.5%；前两个掩码合计覆盖 3.6% 的权重，96.4% 的权重使用单平面；
  - 有效比特预算为 \(B_{\text{eff}} = (1 + f_2)\log_2(3)\)，项目级实测约为 **1.641 比特/权重**，高于单个三值符号的理想信息量 1.585 比特。
- **GPTQ 式误差补偿**：按列量化并将量化误差通过逆 Hessian 传播到剩余列，配置为 WikiText-2 校准、64 样本、序列长度 2048、块大小 128、分组大小 128、order2_group=True、num_p=1、percdamp=0.1、seed=0。

## 3. 实验设计

- **基座模型**：Qwen3-4B，指令微调的 4B 参数稠密模型，36 个 Transformer 层。转换目标是全部 252 个线性张量：MLP 的 gate/up/down 投影加上注意力 q/k/v/o 投影；Embedding 和 LM head 保持 BF16；KOTMS 旋转矩阵为附加连续值参数。共 81.62%（3.633B）参数被量化。
- **困惑度评估**：三个语料库——
  - WikiText-2（全测试集，146 条 2048 token 序列）：13.639 → 18.748；
  - PTB：24.700 → 31.992；
  - C4：19.831 → 28.966；
  - WikiText-2 是校准分布，PTB 与 C4 作为分布外检验，用于排除“校准语料上表现虚高”的假象。
- **能力评估 benchmark**：零样本（zero-shot），使用 lm-evaluation-harness，每任务约 1500 样本、batch size 2：
  - BoolQ、HellaSwag、PIQA、WinoGrande、ARC-Easy、ARC-Challenge、MMLU（含 answer-letter 与 continuation 两种评分协议）、LAMBADA-openai / LAMBADA-standard；
  - 保留度（retention）采用机会校正指标 \(R = (A_s - B)/(A_t - B)\)，其中 B 为 chance 或 majority-class 地板；LAMBADA 因缺乏简单机会地板而标记为“guarded”。
- **质量扫描**：Stage A（主配置，64 样本、percdamp=0.1）→ R1（96 样本，未改善）→ R2（percdamp=0.01，未完成）→ R3（备用校准语料，未开始）。
- **打包实验**：
  - Packing A：格感知的 8.29 GiB → 3.96 GiB 无损级压缩，困惑度基本不变；
  - Packing B：第三方 2 比特有损打包，2.659 GiB 但最大绝对误差 0.305，被明确排除。
- **部署/执行测量**：
  - 重建路径（reconstruction-based）直接对比 FP16 与 W1.58A16 的加载、VRAM、prefill、decode、延迟；
  - Triton GEMV 微基准（4096×2560 投影）对比 FP16 cuBLAS vs. packed Triton vs. chunk-unpack + cuBLAS。

## 6. 主要结论与发现

- **有效比特预算**：量化的线性权重实际为 **1.641 比特/权重**，而非名义上的 1.585；Embedding/LM head 保持 BF16（占总参数约 17.5%），旋转矩阵约 0.90% 为连续值。不能把整个检查点说成“1.58 比特/参数”。
- **能力保留是有分层的**：固定选项任务上准确性均值从 64.5% 降至 54.7%，平均损失 9.8 个百分点。上下文常识类任务保留较好——BoolQ 保留 84.6%、HellaSwag 80.6%、PIQA 73.9%、WinoGrande 72.3%；而知识密集型任务衰减更严重——ARC-Challenge 仅保留 43.8%、MMLU（continuation）50.0%。所有置信区间均不跨零，衰减可检测。
- **困惑度上升依赖评测语料**：WikiText-2 上 1.375×，PTB 上 1.295×，C4 上 1.461×。校准分布效应显著，不能以单个语料的结果作为普适论断。
- **存储压缩是成功的**：实际格感知打包将检查点从 8.29 GiB 降至 3.96 GiB，困惑度与打包前几乎一致（18.344→18.342）。量化与序列化必须区分开——第一个伪量化 FP16 检查点并不减小磁盘占用。
- **执行加速尚未实现**：重建路径比 FP16 更慢（decode 0.78×、延迟 1.29×），初步 Triton 核比 cuBLAS 慢 4.6×（单形状）；压缩本身不产生速度收益。核的密集矩阵运算精度可达 FP16 水平（最大绝对差约 0.00195），瓶颈在于编码/解包流程和核效率。

## 7. 优点

- **四维度分离的评估框架**：将能力、表示、存储、执行分开衡量，避免了用单一“1.58-bit”标签混淆各类属性的常见错误。
- **细致的比特会计**：通过对二阶平面的实际使用比例计算 \(B_{\text{eff}} = 1.641\) 比特/权重，刻画了“自适应有限表示”的真实开销，而非直接套用理想信息量。
- **对保留度指标的修正**：拒绝使用原始精度比，而采用机会校正保留率 \(R = (A_s - B)/(A_t - B)\)，防止 chance 地板不同的任务出现“虚高保留”的假象。
- **跨语料困惑度检验**：补充 PTB/C4 的测试揭示 WikiText-2 作为校准与评测语料的“虚高”风险，体现校准分布效应。
- **打包验证严格**：主打包结果与打包前困惑度逐位核对（0.037% 相对 RMSE），且明确排除了有损第三方打包的 2.659 GiB 数字，防止了“不干净的压缩成绩”污染结论。
- **伪工件检测机制**：通过端到端困惑度验证与离散表示结构检查，识别并拒斥了未真正三值化的 8.5 GiB 伪工件。
- **工程失败模式的透明度**：报告了 autograd 内存泄漏、Windows CUDA 溢出、误判三值工件、断电等边界条件，提高了可复现性与方法论警觉。
- **结论边界清晰**：明确列出不能由此数据支持的声明（如普适加速、SOTA、PTQ 优于 QAT 等），在“解释护栏”方面做得比一般技术报告更克制和诚实。

## 8. 不足与局限

- **独立复现门缺失**：Qwen3-4B 不在 TWLA 原始论文的评测范围内，缺一个已发表参考模型上的复现验证作为最高价值校准。
- **实验覆盖有限**：
  - 单种子、单次运行，未量化 run-to-run 变异；
  - 任务套件较小，缺少对更广泛知识、推理、代码等任务的覆盖；
  - percdamp=0.01、96+ 样本（更大规模）、FineWeb-Edu 校准、num_p=2、group_size=64 等均未完成，无法声明配置为全局最优；
  - Embedding/LM head 的量化未被评估。
- **打包模型的能力评估缺失**：3.96 GiB 的打包工件只验证了困惑度，没有端到端的任务准确率或吞吐量 benchmark。
- **执行评估过于初步**：Triton GEMV 是原型核，只测了一个形状，不能作为三值执行速度的下限或上限结论；重建路径本身是“伪量化”实现，不能代表原生三值执行。
- **部署条件单一**：全部测量基于一张消费级 GPU（RTX 5070）和 Windows 栈，未覆盖数据中心硬件、多卡、批处理服务器场景。
- **偏置风险**：
  - 校准数据来自 WikiText-2 可能导致在分布内评测上夸大保留能力；
  - MMLU 评分协议之间差异巨大（letter vs. continuation），单看任一数字都可能误解模型行为；
  - 能力分层观察来自小规模任务子集，不能上升为因果法则。

**总结**：本文是一个严谨、边界清晰、工程导向的实证研究，证明了一个 4B 预训练模型可以在不经重训练的条件下被压缩到接近三值极限的有效表示（1.

641 比特/权重），加上 Embedding 与 LM head 的 BF16 开销后，整体检查点的实际存储压缩约为 2.1 倍；但这一存储红利并未转化为执行加速。它以一个高置信度的负面证据表明“量化 + 打包 ≠ 端到端提速”，也为后续研究指出了两个明确方向：一是构建真正原生三值/低比特执行栈，使理论比特率与运行时效率对齐；二是在更广泛的任务套件与更多基座模型上验证“能力分层衰减”是普遍规律还是 Qwen3-4B 的个案现象。整体而言，论文的价值不在于给出“1.58-bit 可行”的简单结论，而在于把抽象的低比特标签拆解成可测量、可复核的工程指标，并为每一维度设定了清晰的证据边界。
